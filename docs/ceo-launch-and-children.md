# CEO launch + child companies (dev guide)

This doc covers the **new** Company OS patterns for launching a CEO chat and
working with **child companies** (including external placement). Read this if you
maintain `agents-holding` or create subsidiaries/children.

## Why

Previously, teams often:

1. Opened a bare CLI (`grok` / `claude` / `codex`)
2. Then hop/search for `ceo`
3. Or manually found a child company path and re-read ORG (expensive)

Now the rule is: **`launch.sh` always starts a direct CEO conversation** for a
given company (parent or child), with an optional first prompt, and optional
session continue.

---

## Launch API (all companies)

Shared core:

```text
holding/system/install/launch_company.sh
templates/install/launch_company.sh   # same file, for create-company copy
```

Company entry (**SoT = company `launch.sh`**, calls the core):

```bash
# Parent / top subsidiary
./.agents/<slug>-company/launch.sh <harness|merge> ["prompt…"]
./.agents/<slug>-company/launch.sh <harness|merge> <child-ish> ["prompt…"]

# External child — script lives IN the company (under .agents/, gitignored with it):
<project-root>/.agents/<stem>-company/launch.sh <harness|merge> ["prompt…"]
```

| Arg | Meaning |
| --- | --- |
| `grok` / `claude` / `codex` | Start **CEO** on that vendor CLI |
| `merge` | `company_os.sh all`, then CEO on `runtime_router.toml` **default** runtime (cross-vendor Assign when router `enabled = true`) |
| `"prompt…"` | **First user message** in the CEO session |
| `--fresh` | Do **not** continue the prior session for this cwd |
| `<child-ish>` | Fuzzy child name (parent wrapper only) — see aliases |

**Always CEO.** Do not run a random command and then hop to ceo.

**Session:** default continues the last session for that company cwd (`grok --continue`, `claude --continue`, `codex resume --last`). Use `--fresh` for a new thread.

### Examples

```bash
# Parent CEO on Grok
./.agents/my-app-company/launch.sh grok "status of release"

# Child CEO from parent (fuzzy name)
./.agents/my-app-company/launch.sh grok desk-garden "spike native Unity embed"
./.agents/my-app-company/launch.sh merge dg "continue eng wave"

# External child package (company path)
cd projects/desk-garden
./.agents/desk-garden-company/launch.sh claude "review Service login AC"
./.agents/desk-garden-company/launch.sh merge --fresh "new topic"
```

Low-level Grok-only (still generated by `company_os.sh grok`):

```bash
./.grok/launch-ceo.sh "…"   # equivalent to: launch.sh grok "…"
```

Prefer `launch.sh` so Claude/Codex/merge share one entry.

## Parent → child without opening child ORG

Token-cheap handoff (no ORG/staff crawl):

```text
templates/hop-reference/scripts/handoff_child.py
```

Copied into each company hop tree on create/update.

```bash
# Resolve path / print spawn brief
python3 …/marlin-hop/scripts/handoff_child.py --list
python3 …/handoff_child.py desk-garden --print-path
python3 …/handoff_child.py desk-garden --brief --goal '…'

# Or just use launch.sh (recommended) which maps fuzzy name → path → CEO launch
./.agents/<parent>-company/launch.sh grok desk-garden "…"
```

Fuzzy aliases live in:

```text
…/marlin-hop/data/children_aliases.tsv
# see templates/hop-reference/data/children_aliases.tsv.example
```

`hop.py --path projects/<pkg>/…` still emits `handoff: child` via `children.tsv`.

## Child company placement

| Placement | Company OS location | Parent keeps |
| --- | --- | --- |
| `nested` (default) | `<parent>/children/<stem>/<stem>-company/` | META + GRANTS beside it |
| `external` | `<project-root>/.agents/<stem>-company/` | `<parent>/children/<stem>/{META,GRANTS}.toml` only |

```bash
create-child-company.sh \
  --parent .agents/<parent>-company \
  --name desk-garden \
  --budget medium \
  --project-root /path/to/projects/desk-garden \
  --placement external \
  --grant-path libraries/sources/Service \
  --grant-artifact .agents/<parent>-company/cache/plans/….md
```

**Child is a full Company OS mirror** of the parent formula (own staffs/skills/harness/hop).  
Upward channel = **parent ceo / parent hr**, **not** holding (parent may escalate to holding).

After create:

```bash
<child-company>/system/install/company_os.sh all

# Company SoT only (no package-root launcher):
<path-to>/<stem>-company/launch.sh grok "…"

# External example:
projects/desk-garden/.agents/desk-garden-company/launch.sh grok "…"

# Or from parent:
./.agents/<parent>-company/launch.sh grok <stem> "…"
```

## Create a child — holding scripts only (not hop AI)

```text
user / parent ceo → Assign hr → deal + lock
  → ~/.agents/holding/system/install/create-child-company.sh …
  → <child>/system/install/company_os.sh all
```

**Forbidden:** CEO/IC “just mkdir `.agents/…` and write ORG” or hop-scaffolding a
child tree. That skips META/GRANTS/registry/`launch.sh`/company `README.md`.

Product work after the child exists: parent `launch.sh grok <child> "…"`.

## Checklist for app developers

1. Create company / child via **holding install scripts** + hr lock (`create-company.sh` / `create-child-company.sh`).
2. Run `company_os.sh all` (or `launch.sh merge` once).
3. Day-to-day: **company** `./.agents/<slug>-company/launch.sh grok\|claude\|codex\|merge "prompt"` — always CEO.
4. Parent → child product: **`./.agents/<parent>-company/launch.sh grok <child> "prompt"`** — do not open child ORG.
5. Missing docs/grants from a child: child ceo → **parent ceo** (not holding).
